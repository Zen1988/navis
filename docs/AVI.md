# VMware Avi routing and translation adapter

The partial Controller adapter preserves tenant/cloud/VRF identity, configured VRF static routes, VIPs, listener transports and ranges, pool/pool-group backend candidates, backend ports, TLS metadata and source-translation modes. References use native UUIDs; foreign origins, incomplete pagination and inconsistent object identities are rejected. Only objects associated with the selected VRF and their referenced profiles are retained in the emitted inventory.

A virtual service may establish separate frontend and backend connections. Several pool servers can be eligible. The adapter therefore emits `load_balance` evidence with the explicit `load_balancer_frontend_backend_connections` stage, rather than selecting a server or applying ordinary deterministic DNAT. Source addresses and ports remain unknown; configured SNAT pools and VIP-as-SNAT are candidate configuration, not an observed allocation. Pool-group ratios, priorities and persistence references are retained without simulating runtime selection.

The CLI emits four partial ingestion envelopes: route, interface, NAT and raw topology evidence. VIP interface records describe configured host addresses, not physical Service Engine placement. VRF static routes retain native interface names as details, with no invented interface mapping or installed-forwarding assertion. The existing normalized adapter and worker consume the typed envelopes; map the external device identity to the intended tenant/VRF context and approve the normalized adapter digest before processing.

Authorized trace results expose `load_balancer_evidence` containing matching VIP/listener frontend legs and backend connection candidates. This evidence cannot establish connectivity or a successful session. The generic NAT evaluator leaves load balancing unknown. The evidence query uses snapshots already selected by the authorized graph build.

Remaining development includes Service Engine placement, connected/installed routes, BGP/FIB and HA state, health and runtime pool membership, actual selection/persistence/SNAT allocation, backend connection transport details and return paths. HTTP/L4 policy selection, DataScripts, virtual hosts/SNI, DNS-resolved backends, floating IPs and DSR remain unresolved where present. Live Controller collection, Ansible execution and database/graph/trace integration have not been validated.

See the [collector instructions](../examples/ansible/avi/README.md). Synthetic unit tests cover native identities/pagination, v4/v6 routes and VIPs, listener and backend ports, pool groups, SNAT intent, incomplete conditions, disabled objects, normalized envelopes, CLI exports, candidate budgets and deterministic-NAT rejection.

Verify the configured API version against the actual Controller.
