# BIG-IP management API adapter

The partial F5 adapter reads BIG-IP configuration through iControl REST on the management plane. It preserves stable device identity, partition and route domain, virtual-server destinations/listeners, default pools and member addresses/ports, address/port translation switches, configured source-translation intent, self IPs and static gateway routes. Native full paths identify objects; display names are not global identities.

The partition's collected `defaultRouteDomain` resolves addresses without `%ID`. Explicit route-domain suffixes remain isolated. Missing partition/default-domain associations fail translation. Shared pools in another partition remain unresolved in this slice; route-domain inheritance and cross-domain forwarding are not inferred. VIP masks, source/VLAN constraints, virtual precedence, profiles and traffic policies require more evaluation, so conditions always remain incomplete.

Load-balancer output retains separate frontend/backend candidates, not an arbitrary chosen member or deterministic DNAT session. Disabled members are excluded; configured `up` state is not proof of health. `translatePort=disabled` preserves the requested listener port. Disabled address translation is marked unresolved rather than assigning a pool member destination. Automap does not invent a self-IP allocation. SNAT pool addresses are retained when directly resolved in the selected partition; named translation objects remain unresolved. The source-port mode is preserved without inventing an allocation. Source translation `none` is only virtual-server configuration, not proof that standalone SNAT cannot apply.

Four partial envelopes cover routes, interfaces, NAT and `f5_load_balancer_evidence` topology. Static routes are configured evidence with recursive next hops; installed FIB coverage and interface association remain unknown. Gateway pools, discard routes and dynamic routing are not translated in this slice. Self IPs preserve VLAN/traffic-group references without inventing physical links. VIP interface records do not prove ARP/advertisement, traffic-group ownership or placement.

Authorized database traces include matching entries under `load_balancer_evidence`, tagged with `evidence_kind`. Candidate health, selection, source allocation and connectivity remain unknown. `load_balance` at the `load_balancer_frontend_backend_connections` stage is deliberately unsupported by the ordinary deterministic NAT evaluator.

Remaining work includes live/version validation, database/graph integration, installed routing and HA ownership, virtual selection/precedence, wildcard/network/forwarding virtuals, iRules and LTM policies, profiles/TLS/backend transport, persistence and health, AFM/ASM/APM, standalone SNAT/NAT, named SNAT translations, cross-partition/shared and cross-domain resolution, dynamic routing and return paths. This adapter targets BIG-IP TMOS iControl REST, not BIG-IP Next or BIG-IQ.

See [collection and normalization](../examples/ansible/f5/README.md). Tests use synthetic native-shaped exports and mocked HTTP responses; they do not establish live compatibility.
