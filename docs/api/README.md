# API contract artifacts

Read the [integration guide](../INTEGRATION_API.md) for lifecycle, payload fields, response interpretation and errors. This directory contains a generated [OpenAPI snapshot](openapi.json), eight complete synthetic [request examples](examples/) and [a verification script](verify_contract.py).

Three [response examples](responses/) show an accepted ingestion, a complete unresolved trace response and unavailable recommendations. The unresolved trace is generated by the actual trace implementation with a mocked empty database view; it is not a live network result. Storage and HTTP wrappers are mocked for boundary verification. These are examples, not a closed response schema.

`openapi.json` comes from `navis_api.main.app.openapi()`, without startup or a database. Success responses are dynamic Python dictionaries with no declared response models, so the generated schema does not fully describe their bodies. Use the guide alongside OpenAPI; generated SDK types alone cannot express the current evidence/verdict semantics.

All sample source identities, timestamps and UUIDs are placeholders. Submit each ingestion file separately after replacing identities/time and arranging source permission/mapping/worker processing. The trace example needs a real completed build UUID and a fresh caller session ID. There is no bulk array endpoint or ingestion polling endpoint.

Install the project and the optional HTTP test client in an isolated environment, then run from the repository root:

```text
python -m pip install -e . httpx
python docs/api/verify_contract.py
```

Use `--write` only when intentionally refreshing generated artifacts. The script validates the request models and all seven typed payload kinds, compares artifacts, and exercises real HTTP handlers with fake storage. It makes no external API or live database calls. HTTP client/ASGI libraries may use a local Windows socketpair. The HTTP client is a documentation-check dependency, not a new production requirement. Changes in installed FastAPI/Pydantic versions can affect generated schema; compare the deployed `/openapi.json` and pin your deployment dependencies.
