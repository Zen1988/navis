# Navis v0.1.0

First tagged development release, 2026-11-17. This is a source release; build the
container locally with Docker or Podman. No prebuilt registry image is claimed.

## Included

- Automatic namespace topology attempts after ingestion and stable named
  application topologies selected by server names, external IDs or IPs.
- Content-based graph version reuse: unchanged content keeps its IDs/build date
  and advances its update/check date. History and comparison are name-scoped.
- Managed inventory evidence on both sides of an unmanaged visibility gap,
  without claiming connectivity across an unknown network.
- Ingestion receipts and collection progress: expected/received/processed/pending/
  failed/raw-only counts, adapter/device details and persisted failure reasons.
- Caller-owned traces and session graphs, lifecycle labels, live/audit separation,
  and operator retention tools (90-day eligible inactivity, then one calendar
  year after archival).
- Container-based backup, legacy-baseline adoption and transactional database
  migrations with a checksum ledger.
- Podman-specific Linux/rootless/SELinux instructions and consistent application,
  API, package and image version metadata.

## Upgrade

The API requires database migrations **001–021** before startup. Existing
manually migrated databases must adopt their verified baseline, then apply only
pending migrations with a checked backup. Do not infer the database baseline
from the SQL files present in a checkout. Preserve old images/backups and stop
writers during schema upgrades.

## Validation and limits

318 unit/API tests ran with one database-dependent test skipped, and the checked-in OpenAPI/example contracts passed (nine requests, three response fixtures, 19 API paths). The Python wheel was built to verify package version metadata. Database
migrations/queries and deployment YAML have also received syntax checks. The
release version consistency check covers package metadata, FastAPI and the
default container version. Live PostgreSQL/AGE migrations, restore rehearsals,
container execution and retention still require environment-specific validation.

The engine remains a prototype. Vendor semantics, workload resolution, installed
forwarding/policy coverage and return-path evidence are incomplete; unknown
results must not be promoted to allow. Successful ingestion is not proof of a
working network path. Retention defaults to preview and requires explicit
operator `--apply`/scheduling; active and retained dependencies stay protected.
